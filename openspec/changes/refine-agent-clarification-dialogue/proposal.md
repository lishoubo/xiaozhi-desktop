# Proposal

## Why

同一业务执行发生多轮参数补全时，最新交互卡会被挂到此前所有系统追问消息下；取消补全则静默删除卡片，历史对话无法解释任务为何停止。当前快捷入口也不足以覆盖运营人员常见的趋势、月度进度和渠道对比任务。

## What changes

- 已提交的补全卡立即退出可编辑状态，由持久化的用户回答承接对话。
- 后续仍需补充时，只在最新系统追问下展示一张新卡。
- 取消补全时持久化“取消本次任务”和系统确认消息。
- 新增近 7 日趋势、本月经营进度、渠道经营对比三个只读快捷操作。

## Success criteria

- 任一时刻同一业务执行最多展示一张可编辑补全卡。
- 提交后旧卡立即消失；后续追问不会回挂到旧消息。
- 取消后重新打开会话仍能看到取消语义。
- 三个新增快捷操作走既有受限只读 DMS 流程。
