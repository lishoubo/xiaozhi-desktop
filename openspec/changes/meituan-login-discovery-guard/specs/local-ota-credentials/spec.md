## ADDED Requirements

### Requirement: 美团发现只核验当前有效登录身份

系统 MUST 区分本地凭证 ID 与美团渠道账号 ID。打开已有美团凭证时，若该凭证已有渠道账号 ID，系统 MUST 仅以该 ID 发起定向身份核验，不得遍历历史缓存中的其他账号 ID。登录成功的判定 MUST 依据当前会话返回的有效账号身份，不能只依据目标 URL、已有凭证记录或历史缓存。身份未确认时 MUST 保留原有凭证及酒店绑定，不得报告重新登录成功。

#### Scenario: 已选账号的旧登录态失效

- **WHEN** 用户选择已有美团凭证重新登录，当前会话已跳转到美团登录页或身份接口返回未登录
- **THEN** 系统停止本次定向身份核验，不继续请求其他历史账号
- **AND** 系统不报告重新登录成功，也不修改该凭证的身份或酒店绑定
- **AND** 用户仍可在标签页中手动登录，登录状态变为可核验后才能继续

#### Scenario: 已选账号重新登录成功

- **WHEN** 用户选择已有美团凭证，当前会话返回有效账号身份且其渠道账号 ID 与所选凭证一致
- **THEN** 系统继续现有重登核对和结果处理
- **AND** 定向身份核验至多请求所选渠道账号一次，不枚举历史候选

#### Scenario: 已选账号登录为其他美团账号

- **WHEN** 当前会话的有效身份无法证明是所选渠道账号
- **THEN** 系统不得凭所选凭证的本地记录认定登录成功
- **AND** 不得把其他账号的会话写入原绑定

### Requirement: 美团无已知账号 ID 时须先确认登录再发现身份

系统 MUST 在当前会话被确认有效后，才尝试从页面状态发现没有预先传入 ID 的美团账号。历史缓存中存在多个候选时，系统 MUST NOT 对所有候选逐个发账号详情请求；无法唯一确定当前账号时 MUST 明确返回身份未确定，并等待新的登录状态或用户操作。一次发现的网络请求 MUST 有时限；标签关闭或页面转回登录页后，过期结果 MUST NOT 写入凭证。

#### Scenario: 新登录后只有一个当前账号候选

- **WHEN** 用户完成美团登录，当前会话已被确认有效，且能唯一确定一个渠道账号 ID
- **THEN** 系统只核验该账号身份，并在有效响应后继续现有发现流程

#### Scenario: 登录页保留多条历史候选

- **WHEN** 用户尚未登录或当前账号无法从多条历史候选中唯一确定
- **THEN** 系统不逐个请求这些候选的账号详情
- **AND** 系统不创建或刷新凭证，向等待中的操作返回可恢复的身份未确定结果

#### Scenario: 身份请求超时或页面离开

- **WHEN** 身份核验超过有限时长，或所属标签已关闭、当前页面已回到登录页
- **THEN** 系统停止或作废本次发现结果
- **AND** 系统记录不含账号值、Cookie、原始响应的失败类别，以便定位问题
