# Proposal: 修复 Agent 滚动、渠道查询与失败状态恢复

## 背景

历史会话打开后未定位到最新消息，运行过程中新增消息和执行事件也不会持续推动对话区到底部。与此同时，“渠道经营对比”会在完成 DMS schema 探索和 SQL 生成后触发执行协议失败；失败的业务执行仍可能被客户端识别为等待补充，导致后续快捷操作被错误拦截。

## 目标

- 打开历史会话后将对话区定位到最新内容。
- 用户位于对话底部时，新消息、流式回答、工具时间线和补充卡片持续自动滚动；用户主动向上阅读时不强行抢回位置。
- 让“渠道经营对比”在既定工具预算内完成真实 DMS 查询，并保留只读与证据校验约束。
- 任何终止失败都必须把业务执行收敛到失败状态，不能残留为 `awaiting_clarification` 或其他非终态而阻塞新任务。

## 非目标

- 不改变 DMS 数据口径或新增写操作。
- 不允许同一会话并发执行多个业务任务。
- 不重构无关 Agent UI 或执行层。

## 成功标准

- 历史会话打开后可见最后一条内容。
- 正常跟随模式下，新增内容始终可见；用户向上滚动后保留阅读位置，回到底部后恢复跟随。
- 指定“银际酒店（包头青山文化路王府井店）”的渠道经营对比不会因工具调用预算而在 SQL 执行前失败。
- 失败后的会话可以立即启动另一快捷操作，且不会显示错误的等待补充提示。
