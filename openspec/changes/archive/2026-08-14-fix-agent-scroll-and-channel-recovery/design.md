# Design: Agent 对话滚动与执行状态收敛

## 1. 对话滚动

在 `AgentPage` 的对话滚动容器底部放置稳定锚点，并维护“是否跟随最新内容”的非业务 UI 状态：

- 切换或首次打开会话：数据加载并完成 DOM 更新后无动画定位到底部。
- 消息、草稿、执行时间线、补充卡片等可见内容变化：仅在用户原本接近底部时滚动到底部。
- 用户主动向上滚动超过阈值：暂停自动跟随，避免打断历史阅读。
- 用户重新滚动到底部：恢复跟随。

使用 Svelte 5 的响应式副作用只同步 DOM 这一外部系统；滚动事件直接更新跟随状态。

## 2. 渠道对比工作流

渠道对比仍归入 `generic_hotel_data_query`，因为查询需要模型依据实际 schema 选择渠道字段。当前执行协议允许的工具预算必须覆盖固定链路：数据库发现由服务端适配器完成，Agent 可执行表清单、必要的表结构查看、SQL 生成与 SQL 执行。预算校验应以业务意图注册表中的上限为准，并给渠道探索留出一次额外 schema 查看空间；不得移除 SQL 最终执行与证据校验要求。

同时收紧提示：SQL 生成结果不是证据，生成后必须调用查询工具；避免模型在重复描述表结构上耗尽预算。

## 3. 失败状态收敛

Run 失败处理必须同步推进关联业务执行：

1. 将 Run 标记为 `failed` 并发布 `run_failed`。
2. 若业务执行仍是非终态，将其显式转换为 `failed`，保存可重试性和失败原因。
3. 会话刷新后，前端只把真正的 `awaiting_clarification` 视为待补充任务。

该修复放在服务端失败边界，覆盖协议、MCP、模型及持久化之外抛出的所有运行失败，而不是只针对某个快捷操作。

## 4. 验证

- 服务端单元测试：渠道工作流预算/工具链，异常时业务执行进入失败终态。
- Desktop 组件或 E2E 定向测试：历史会话打开和新增内容自动滚动；向上阅读不被强制拉回。
- Svelte autofixer、受影响 workspace 检查和定向测试。
