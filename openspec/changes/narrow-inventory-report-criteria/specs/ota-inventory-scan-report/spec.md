## Purpose

定时扫描把渠道当前状态与本地基线逐格比对后，判断**哪些差异值得上报**。房态与房量的判据不同：
房态任何改变都是渠道事实，而房量会因正常销售持续波动，只有配额变化与售罄跃迁才需要跟进。

## ADDED Requirements

### Requirement: 房态改变一律上报

房态是渠道侧的经营动作（开关房、系统关房），没有「正常波动」一说。系统 SHALL 在房态字段
发生任何变化时上报，不附加任何额外条件。

#### Scenario: 房态由开变关

- **WHEN** 某格的房态字段与基线不同
- **THEN** 系统上报该格

#### Scenario: 房态取值是未见过的枚举

- **WHEN** 渠道返回的房态取值不在已知枚举内
- **THEN** 系统仍按「有改变就报」上报，不因无法解读而丢弃

### Requirement: 房量仅在总量变化或售罄跃迁时上报

酒店有订单时房量本就会变（卖出一间 → 已售增加、可售减少），这类变化不构成需要跟进的渠道事实。
系统 SHALL 仅在满足以下任一条件时上报房量变化：

1. **总房量**（用户设定的配额）与基线不同
2. **可售房量**由非 0 变为 0

其余房量变化 SHALL NOT 触发上报。

#### Scenario: 卖出一间但配额未变

- **WHEN** 某格的已售增加、可售减少，且总房量与基线相同
- **AND** 可售房量仍大于 0
- **THEN** 系统不上报该格

#### Scenario: 用户在渠道后台改了配额

- **WHEN** 某格的总房量与基线不同
- **THEN** 系统上报该格

#### Scenario: 最后一间售出

- **WHEN** 某格可售房量由非 0 变为 0
- **THEN** 系统上报该格

### Requirement: 售罄只报跃迁，不报持续状态

售罄是一个持续状态，每轮扫描都上报会让同一格重复刷屏。系统 SHALL 只在「可售房量由非 0 变为 0」
的那一轮上报；已经为 0 且保持为 0 的格子 SHALL NOT 重复上报。

#### Scenario: 连续多轮保持售罄

- **WHEN** 某格上一轮可售房量已为 0，本轮仍为 0
- **AND** 总房量未变
- **THEN** 系统不上报该格

#### Scenario: 售罄后重新有房再次售罄

- **WHEN** 某格可售房量由 0 恢复为正数，其后再次变为 0
- **THEN** 系统在再次变为 0 的那一轮上报

### Requirement: 房量口径按渠道各自计算

两个渠道的房量字段名与语义都不同，且都存在「看起来是房量但不是」的字段。系统 SHALL 按渠道
各自的口径计算总房量与可售房量，SHALL NOT 跨渠道套用同一字段名。

系统 SHALL 把「不限量」与「可售为 0」区分开：不限量模式下渠道的房量数字不代表真实房量，
按数字判定会把不限量的房型误判成售罄。

#### Scenario: 渠道处于不限量模式

- **WHEN** 某格所在渠道标记为不限量模式
- **THEN** 系统不因该格房量数字为 0 而判定为售罄

#### Scenario: 渠道以哨兵值表示不限量

- **WHEN** 渠道在不限量模式下返回一个远大于真实房量的哨兵数字
- **THEN** 系统不把该数字当作总房量参与比较

#### Scenario: 渠道的有房标记未区分不限量与售罄

- **WHEN** 渠道自身的有房标记在不限量模式下与真售罄取值相同
- **THEN** 系统先判定是否不限量，不单凭该标记判定售罄

### Requirement: 首次见到的格子只建基线不上报

基线天然稀疏，「基线里没有」不代表渠道刚刚新增。系统 SHALL 对基线中不存在的格子只写入基线、
不上报，房量判据 SHALL NOT 改变这一既有行为。

#### Scenario: 扫描到一个从未读过的格子

- **WHEN** 某格在基线中不存在
- **THEN** 系统写入基线且不上报，无论其房量为何值

### Requirement: 收窄判据不改变上报体结构

本能力只决定**是否上报**，不决定**报什么**。系统 SHALL 保持上报体的既有结构与字段不变，
使服务端无需因判据收窄而改动解析逻辑。

#### Scenario: 一格同时满足房态与房量判据

- **WHEN** 某格的房态与总房量同时发生变化
- **THEN** 系统按既有结构上报该格一次，不拆成两条

### Requirement: 既有基线不得因本次变更失效

内容指纹的参与字段与其拼接顺序决定了全部既有基线的可比性。系统 SHALL NOT 变更内容指纹的
字段集合或顺序 —— 任何变更都会让既有基线在下一轮扫描中被整体判成变更，产生一次全窗口误报。

#### Scenario: 变更上线后的第一轮扫描

- **WHEN** 收窄判据上线后首次扫描
- **THEN** 系统仅上报真实发生变化的格子，不产生全窗口误报
