## Purpose

定义 desktop 在应用内打开自有 RMS web 页面（区别于 OTA 商家后台）的规则：入口如何与
OTA 渠道区分、登录态如何从主进程传给页面、会话过期归谁处理，以及这条链路必须与 OTA
标签页链路保持哪些隔离。

## ADDED Requirements

### Requirement: 内部页面入口与 OTA 渠道入口视觉同列但行为分离

系统 MUST 在渠道工作区把内部页面入口与 OTA 渠道入口并列展示，使用户不必区分两者的技术
差异。但内部页面 MUST NOT 参与任何 OTA 账号语义：MUST NOT 出现在账号切换、新建登录、
导入 Cookie 等入口中，MUST NOT 出现在酒店绑定的可选渠道中，MUST NOT 被历史绑定记录的
渠道名反查命中。

点击内部页面入口 MUST 直接打开该页面，不经过账号选择。

#### Scenario: 点击内部页面入口

- **WHEN** 用户点击内部页面入口
- **THEN** 系统直接打开该页面的标签页
- **AND** 不展示账号切换或登录方式选择

#### Scenario: 内部页面不出现在绑定流程

- **WHEN** 用户进入酒店绑定流程选择渠道
- **THEN** 候选渠道中不含任何内部页面

#### Scenario: 历史绑定记录的渠道名反查

- **WHEN** 系统把一条历史绑定记录的渠道标识翻译成展示名
- **THEN** 内部页面的标识不参与该翻译

### Requirement: 登录态由主进程持有并在打开时注入

系统 MUST 由主进程在每次打开内部页面时取一个当前有效的 RMS 访问令牌，随页面地址传给
页面。主进程 MUST NOT 把刷新令牌交给页面 —— 登录态的持有者是主进程，页面只是显示层，
把长效凭证交给页面等于让它自行续期，与该职责划分矛盾。

无有效 RMS 会话时 MUST NOT 打开页面，而是如实报错。用户在未登录状态下不可能到达该入口，
但该入口 MUST NOT 依赖这一前提静默打开一个未登录的页面。

系统 MUST NOT 把访问令牌写入日志、错误上报或任何持久化记录。

#### Scenario: 已登录时打开

- **WHEN** 用户在已登录状态下打开内部页面
- **THEN** 系统取一个当前有效的访问令牌并随地址传给页面
- **AND** 不传递刷新令牌

#### Scenario: 令牌临近过期

- **WHEN** 打开页面时主进程持有的访问令牌已过期或临近过期
- **THEN** 系统先续期再取令牌，传给页面的令牌为续期后的新令牌

#### Scenario: 无有效会话

- **WHEN** 主进程无有效 RMS 会话
- **THEN** 系统不打开页面并报错

#### Scenario: 令牌不落记录

- **WHEN** 打开内部页面的过程被记录到日志或错误上报
- **THEN** 记录中不含访问令牌

### Requirement: 页面会话过期由主进程续期，用户无感

页面在登录态失效时会跳转到 RMS 登录页。系统 MUST 拦截内部页面标签页中**目标为 RMS
登录页**的导航，MUST NOT 让该页面真的落到 RMS 登录页上 —— desktop 用户不具备在那里
重新登录的手段（其登录入口在应用自身，且可能是短信登录），落过去即是死路。

拦下后系统 MUST 取一枚当前有效的访问令牌并用它重新加载该页面。主进程会话也已失效时，
系统 MUST 关闭该标签页并引导用户走应用自身的登录流程。

系统 MUST 对同一标签页的连续拦截设上限，超过后 MUST 关闭标签页而非无限重载 ——
续期成功却仍被跳转时，无上限的重载会变成死循环。

拦截 MUST 只作用于内部页面的标签页，且 MUST 只在导航目标为登录页时生效；其余导航
一律放行。

#### Scenario: 令牌过期后页面尝试跳登录页

- **WHEN** 内部页面因令牌过期而尝试导航到 RMS 登录页，且主进程仍有有效会话
- **THEN** 系统阻止该次导航
- **AND** 取一枚新的访问令牌重新加载该页面
- **AND** 用户无需任何操作

#### Scenario: 主进程会话也已失效

- **WHEN** 内部页面尝试导航到 RMS 登录页，且主进程取令牌时判定会话已失效
- **THEN** 系统关闭该标签页
- **AND** 不把用户留在 RMS 登录页上

#### Scenario: 续期后仍反复跳转

- **WHEN** 同一标签页的登录页跳转被连续拦截并超过上限
- **THEN** 系统关闭该标签页，不再继续重载

#### Scenario: 页面内的正常导航不受影响

- **WHEN** 内部页面发生目标不是登录页的导航
- **THEN** 系统不拦截

### Requirement: 内部页面不触发任何 OTA 渠道行为

系统 MUST 保证内部页面的标签页不触发 OTA 专属流程：MUST NOT 做登录判定、MUST NOT 做
门店探测、MUST NOT 采集或写入渠道登录凭证、MUST NOT 监听价量态改动并上报。

#### Scenario: 内部页面导航不触发渠道流程

- **WHEN** 内部页面标签页发生页面导航
- **THEN** 系统不进行登录判定、门店探测、凭证采集或改动上报

### Requirement: 当前酒店以服务端记录为准

系统 MUST NOT 在打开内部页面时指定酒店 —— desktop 不维护「当前酒店」这一状态，指定
一个来源不明的酒店 ID 会让改价落到错误的酒店上。页面显示哪家酒店 MUST 由服务端记录的
当前酒店决定。

#### Scenario: 打开内部页面时的酒店归属

- **WHEN** 系统打开内部页面
- **THEN** 地址中不含酒店标识
- **AND** 页面显示服务端记录的当前酒店
