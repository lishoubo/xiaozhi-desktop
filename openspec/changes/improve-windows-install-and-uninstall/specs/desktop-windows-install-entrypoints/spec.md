## Purpose

让 Windows 用户在重新安装前发现正在运行的应用或安装器，并能从发布包里找到标准卸载入口，减少文件占用导致的安装失败，同时保留本地业务数据。

## ADDED Requirements

### Requirement: Windows 发布包提供安装前检查入口

Windows 发布包 SHALL 同时提供原始 Squirrel `setup.exe` 和同目录的 `<产品名>安装程序.exe`。入口 SHALL 在启动原始安装程序之前检查本应用是否正在运行，并阻止同一安装入口的并行执行；若发现冲突，SHALL 显示可见提示并停止本次安装。入口 SHALL 将检查结果、原始 Setup 路径及退出码写入可供用户取得的日志，并在失败提示中显示日志路径。入口 SHALL 不删除原始 Setup 或自身。

#### Scenario: 应用正在运行
- **WHEN** 用户通过安装入口安装且本应用进程仍在运行
- **THEN** 用户看到先退出应用的提示，原始安装程序未被启动

#### Scenario: 同一安装入口正在运行
- **WHEN** 用户通过安装入口安装且另一个相同入口的实例仍在运行
- **THEN** 用户看到等待前一次安装结束的提示，新的安装程序未被启动

#### Scenario: 可以安装
- **WHEN** 未检测到冲突进程
- **THEN** 安装入口运行同目录的原始安装程序并等待其结束，发布目录中的两个 EXE 均保留

### Requirement: Windows 发布包提供普通卸载入口

Windows 发布包 SHALL 提供可发现的普通卸载入口，调用当前用户的标准 Squirrel 卸载流程。该入口 SHALL 不删除应用用户数据。

#### Scenario: 已安装
- **WHEN** 用户启动普通卸载入口且当前用户已安装本应用
- **THEN** 入口运行标准卸载程序，清理其管理的应用安装文件、快捷方式与卸载项

#### Scenario: 未安装
- **WHEN** 用户启动普通卸载入口且当前用户没有对应安装
- **THEN** 入口显示未找到安装的提示，且不清理其他目录
