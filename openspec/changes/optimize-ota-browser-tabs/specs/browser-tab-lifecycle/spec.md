## Purpose

定义 OTA 标签页**视图本身**的生命周期：谁负责激活、视图在什么条件下可见、页面故障如何
呈现给用户、标题如何显示、以及同时打开的标签页数量如何约束。

与 `browser-partition-lifecycle` 的分工：那份规范回答「这个标签页用哪份登录态」，本能力
回答「这个标签页作为一个视图如何被管理」。两者都提到标签页，但约束的是正交的两件事。

## ADDED Requirements

### Requirement: 标签页视图的可见性独立于其尺寸

系统 MUST 用独立的可见性状态表达「标签页暂时不可见」，MUST NOT 通过把视图尺寸设为零来
表达该语义。

原因是竞态：让位与尺寸同步是两条并发的异步链，若两者都通过尺寸表达意图，最终落地的尺寸
取决于到达顺序。零尺寸视图仍会正常上报标题与加载状态，故障表现为「标签页标题更新了、
内容区却看不见任何东西」，且不可稳定复现。

内容区被应用内弹窗占用期间，系统 MUST 使当前标签页视图不可见；弹窗关闭后 MUST 恢复可见。
恢复可见 MUST NOT 依赖重新计算并下发尺寸。

#### Scenario: 弹窗占用内容区

- **WHEN** 应用内弹窗需要占用内容区
- **THEN** 当前标签页视图变为不可见
- **AND** 该视图记录的尺寸保持不变

#### Scenario: 弹窗关闭后恢复

- **WHEN** 占用内容区的弹窗关闭
- **THEN** 当前标签页视图恢复可见
- **AND** 恢复过程不依赖重新下发尺寸

#### Scenario: 让位期间打开新标签页

- **WHEN** 内容区正在让位给弹窗期间有新标签页被打开并激活
- **THEN** 该标签页的尺寸正常生效
- **AND** 弹窗关闭后该标签页内容可见

### Requirement: 网页自行打开的标签页走统一的激活流程

当网页自身请求打开新窗口时，系统 MUST 以与其他打开入口相同的流程完成收尾：标签页进入
标签栏、成为所属渠道的活动标签页、并按当前视口尺寸布局。

系统 MUST NOT 在界面不知情的情况下直接把新标签页的视图放入内容区。此前网页自开的标签页
由主进程直接激活，界面只能通过状态变更事件得知它的存在，无法为它同步视口尺寸——这是零
尺寸视图的来源之一。

#### Scenario: 网页请求打开新窗口

- **WHEN** 网页脚本或链接请求打开一个新窗口
- **THEN** 系统在同一登录态下创建新标签页
- **AND** 界面收到通知并完成与其他入口一致的收尾

#### Scenario: 新标签页的尺寸已就位

- **WHEN** 网页自行打开的标签页完成激活
- **THEN** 该标签页视图的尺寸等于当前内容区的实际尺寸

### Requirement: 标签页故障必须可见且可恢复

系统 MUST 捕获标签页的三类故障事实并反映到该标签页的状态中：渲染进程终止、主框架加载
失败、页面无响应。每一类 MUST 使该标签页退出加载中状态，并 MUST 提供显式的重新加载入口。

系统 MUST NOT 把用户主动中止的加载当作失败上报——单页应用的内部导航会频繁产生中止，
将其计为故障会使故障提示失去意义。

系统 MUST 记录故障的结构化日志，包含渠道标识与故障原因。

#### Scenario: 渲染进程终止

- **WHEN** 某标签页的渲染进程终止
- **THEN** 该标签页状态标记为已崩溃且不再处于加载中
- **AND** 界面为该标签页提供重新加载入口

#### Scenario: 主框架加载失败

- **WHEN** 某标签页的主框架加载失败
- **THEN** 该标签页状态标记为加载失败且不再处于加载中
- **AND** 界面为该标签页提供重新加载入口

#### Scenario: 用户中止的加载不算失败

- **WHEN** 页面导航被主动中止
- **THEN** 系统不把它记为加载失败

#### Scenario: 从故障中恢复

- **WHEN** 用户对一个处于故障状态的标签页触发重新加载
- **THEN** 该标签页重新加载其地址
- **AND** 故障状态被清除

### Requirement: 标签页标题完整可读

系统 MUST 使用户能够读到标签页的完整标题，即使标签栏中的显示被截断。

系统 MUST 在展示前清洗渠道后台标题中的冗余部分，使截断后剩余的文字仍具区分度。

标签页尚未取得标题或处于故障状态时，系统 MUST 显示描述当前状态的占位文字；引用标签页
标题的辅助文本 MUST 使用同一份文字，不得出现「关闭 正在加载…」这类由占位文字拼出的表述。

#### Scenario: 标题被截断

- **WHEN** 标签页标题长度超出标签可显示宽度
- **THEN** 用户可通过悬停等方式读到完整标题

#### Scenario: 标题含渠道冗余后缀

- **WHEN** 渠道后台页面的标题包含固定的渠道名后缀
- **THEN** 标签栏展示的标题已去除该后缀

#### Scenario: 标签数量少时标题显示更多

- **WHEN** 某渠道下打开的标签页数量较少
- **THEN** 单个标签页可占用更大宽度以显示更多标题文字

### Requirement: 同时打开的标签页数量受限

系统 MUST 限制同时打开的标签页总数。达到上限后，系统 MUST 拒绝创建新标签页并告知用户
原因，MUST NOT 静默丢弃创建请求。

系统 MUST 对网页自行连续打开新窗口的行为做节流：短时间内超过阈值的请求 MUST 被拒绝。

每个标签页承载一个独立的渲染进程，数量无上限时，行为异常的第三方页面可通过连续开窗
耗尽内存。

#### Scenario: 达到数量上限

- **WHEN** 已打开的标签页达到上限且用户请求新建标签页
- **THEN** 系统拒绝创建
- **AND** 界面告知用户已达上限

#### Scenario: 网页连续开窗

- **WHEN** 同一标签页在短时间内连续请求打开新窗口且超过阈值
- **THEN** 系统拒绝超出阈值的请求
- **AND** 记录结构化日志

### Requirement: 关闭活动标签页后内容区不留空白

当被关闭的标签页是当前活动标签页时，系统 MUST 使内容区在同一次操作内接管到另一个标签页，
不得停留在无活动标签页的状态等待界面发起第二次激活。

该渠道下已无其他标签页时，系统 MUST 使内容区进入明确的空态。

#### Scenario: 关闭活动标签页且同渠道还有其他标签页

- **WHEN** 用户关闭当前活动标签页
- **AND** 同渠道下仍有其他标签页
- **THEN** 内容区在同一次操作内切换到相邻标签页

#### Scenario: 关闭最后一个标签页

- **WHEN** 用户关闭某渠道下的最后一个标签页
- **THEN** 内容区进入空态
- **AND** 界面显示相应的空态提示
