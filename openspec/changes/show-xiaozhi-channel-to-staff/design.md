## Context

现有 `SHOW_XIAOZHI_CHANNEL` 是构建期开关，线上包从工作区数组中移除入口。登录身份已有 `userType`，主进程内部页面 IPC 目前仅检查有效令牌，并会优先复用已打开页面。内部页面使用固定 partition，打开时注入短期 access token。

## Goals / Non-Goals

**Goals:** 对线上及预发、开发环境采用同一 `STAFF` 判据；主进程拒绝非服务商打开；会话结束后不恢复旧内部标签。

**Non-Goals:** 不改 RMS 统一改价业务权限，不改 access token 续期或 partition 布局。

## Decisions

1. 入口使用 `userType === 'STAFF'` 的精确判断。既有酒店管理模块将缺失类型视作员工，但这里的要求是仅服务商可见，因此缺失值须默认拒绝。保留 `OTA_CHANNELS` 字典中的内部页面定义，只过滤工作区入口。
2. 主进程在复用旧页面之前读取当前会话并检查类型。只在渲染层隐藏入口无法阻止直接 IPC 调用或旧标签恢复。会话结束回调关闭内部页面，渲染层同时丢弃内部标签状态。
3. 保持现有短期 access token 注入、导航至登录页时续期的机制；它与本次身份可见性无关。

## Risks / Trade-offs

- 身份读取需要一次 RMS `/me` 请求，失败时不能打开页面；这是限制访问时的默认拒绝。
- RMS 页面和接口的最终业务授权位于相邻项目，本仓库只能确保桌面端入口与打开操作的边界。
