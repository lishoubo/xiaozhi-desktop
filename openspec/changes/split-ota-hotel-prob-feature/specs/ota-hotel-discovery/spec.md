## Purpose

定义登录成功后独立探测并持久化 OTA 酒店列表信息的行为契约：探测触发不依赖账号
身份归并流程，按渠道各自决定何时、如何获取酒店数据，并保存到独立的酒店探测记录。

## ADDED Requirements

### Requirement: 酒店探测独立于账号身份归并触发

系统 MUST 在标签页导航事件发生时，独立判断当前页面是否可读取酒店列表，不依赖
账号身份归并流程是否已经执行或完成。系统 MUST NOT 阻塞或延迟账号身份归并流程
等待酒店探测完成。标签页导航事件本身 MUST 只表达"导航发生了"这一客观事实，不
携带账号身份归并流程产出的任何业务判断结果；酒店探测的触发判断由订阅方自行
完成，不依赖账号身份归并流程广播业务语义。

#### Scenario: 账号身份归并与酒店探测互不阻塞

- **WHEN** 标签页导航到登录后页面
- **THEN** 账号身份归并流程按现有规则独立执行
- **AND** 酒店探测流程独立判断是否触发，不等待账号身份归并流程的结果

### Requirement: 酒店探测按凭证去重

系统 MUST 在触发酒店探测前，检查该渠道账号凭证是否已存在酒店探测记录；已存在
时不得重复发起酒店探测动作。

#### Scenario: 已探测过的凭证再次导航到可探测页面

- **WHEN** 某 `OtaCredential` 已有关联的酒店探测记录
- **AND** 该凭证对应的标签页再次导航到可读取酒店列表的页面
- **THEN** 系统不重复发起酒店探测

#### Scenario: 尚未探测过的凭证到达可探测页面

- **WHEN** 某 `OtaCredential` 尚无关联的酒店探测记录
- **AND** 该凭证对应的标签页导航到可读取酒店列表的页面
- **THEN** 系统发起对应渠道的酒店探测

### Requirement: 抖音酒店探测不与账号身份读取共享页面操作

系统 MUST 将抖音酒店探测（点击门店管理菜单、捕获酒店列表接口响应）与抖音账号
身份读取在时间上分离执行，不得在同一次页面操作窗口内同时进行两者，避免同一
`webContents` 的调试协议连接被重复占用。

#### Scenario: 抖音账号身份读取与酒店探测顺序执行

- **WHEN** 抖音登录后页面触发账号身份读取
- **THEN** 账号身份读取完成后，酒店探测才开始独占页面操作
- **AND** 两者不在同一时间窗口内同时操作页面

### Requirement: 携程酒店探测从已归并的凭证信息翻译，不重复读取页面

系统 MUST 在携程场景下，通过已归并保存的 `OtaCredential` 附加信息翻译出酒店
信息，不得为酒店探测重新读取或操作携程页面。携程酒店探测触发方式、去重规则、
持久化方式与其他渠道保持一致，仅探测手段不同。

#### Scenario: 携程凭证已包含酒店信息

- **WHEN** 携程账号身份归并流程已保存包含酒店 ID 与名称的凭证附加信息
- **AND** 酒店探测判定该凭证尚无酒店探测记录
- **THEN** 酒店探测直接从凭证附加信息翻译出酒店记录并保存
- **AND** 系统不读取或操作携程页面获取酒店信息

### Requirement: 酒店探测记录独立持久化

系统 MUST 将酒店探测结果保存到独立于 `OtaCredential`/`OtaAccount` 的记录，字段
包含：所属凭证标识、渠道、OTA 酒店 ID、酒店名称（可空）、渠道原始绑定信息
（可空 JSON）、发现时间。记录的（渠道、OTA 酒店 ID）组合 MUST 唯一。

#### Scenario: 新酒店探测结果写入

- **WHEN** 某渠道酒店探测返回一个此前未记录的（渠道、OTA 酒店 ID）组合
- **THEN** 系统创建一条新的酒店探测记录，关联触发本次探测的凭证

#### Scenario: 已有酒店重新探测

- **WHEN** 某渠道酒店探测返回一个已存在记录的（渠道、OTA 酒店 ID）组合
- **THEN** 系统更新该记录的凭证关联、酒店名称、渠道绑定信息和发现时间

### Requirement: 酒店探测记录保存渠道化绑定上下文

系统 MUST 在酒店探测记录的渠道绑定信息字段中保存探测阶段获得的渠道原始绑定
数据。该字段 MUST 是可空 JSON，并按渠道校验；系统不得为当前未确认的字段制造
占位值。

#### Scenario: 抖音酒店保存商户组

- **WHEN** 抖音酒店探测结果包含 `groupId`
- **THEN** 系统将其保存为绑定信息中的 `merchantGroupId`

#### Scenario: 美团酒店保存合作方信息

- **WHEN** 美团酒店探测结果包含合作方 ID 与名称
- **THEN** 系统将其保存为绑定信息中的 `otaPartnerId` 与 `otaPartnerName`

#### Scenario: 携程当前没有额外绑定信息

- **WHEN** 携程酒店探测结果没有已确认的渠道原始字段
- **THEN** 系统将绑定信息字段保存为 `null`

### Requirement: 酒店探测前校验页面可信域名

系统 MUST 在发起酒店探测动作前，校验当前页面属于该渠道预期的受信任 HTTPS 域名；
不受信任时 MUST NOT 执行探测脚本或页面操作。

#### Scenario: 页面域名不受信任

- **WHEN** 标签页当前 URL 不属于目标渠道预期的受信任 HTTPS 域名
- **THEN** 系统不发起酒店探测
- **AND** 不创建或更新酒店探测记录
