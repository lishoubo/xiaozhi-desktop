# 携程账号身份踩点

> 2026-08-14，真机（`ebooking.ctrip.com/home/mainland`，已登录单店账号）经 CDP 读取。
> 为 `harden-tab-partition-lifecycle` 的 T4（携程多门店账号无法绑定）取证。

## 结论

携程**把账号和酒店明确分成两组标识**，各有各的 ID 和名字。现有代码
（`main/channels/ctrip/discovery.ts:51`）把**酒店 ID 当账号身份**，是把两个概念混成了一个。

| | 账号 | 酒店 |
|---|---|---|
| ID | `huid` = `12324831` | `masterHotelId` = `85068938` |
| 名 | `userName` = 银际青山店 | `hotelName` = 银际酒店(包头市青山王府井文化路店) |

两者独立，多门店账号下 `huid` 不变而酒店会有多个。

## 旁证：同一份身份在四处重复出现

`huid` 与 `masterHotelId` 的配对关系被页面反复写在多个地方，可交叉验证：

```
cookie  imislogin                      = "12324831^1"                    ← 账号 ID
localStorage HEMicroUserTag            = HEUserHotelTag_12324831_85068938  ← 账号_酒店
localStorage calendarInventoryFilter_85068938_12324831                    ← 酒店_账号
window.HEUbtBaseData                   = { huid, masterHotelId, hotelName, username, userType }
window.MicroMainConfig.HEMicroUserTag  = 同上
DOM a.he-ctrip-hotel-title-link href   = /hotels/85068938.html            ← 仅酒店（现有代码只读这个）
```

`window.HEUbtBaseData` 是不用调函数的兜底来源，字段较少但账号/酒店都在：

```js
{ huid: 12324831, username: "银际青山店", masterHotelId: 85068938,
  hotelName: "银际酒店(包头市青山王府井文化路店)", userType: "HOTEL",
  star: 4, country: 1, province: 28, city: 141 }
```

## 多门店相关字段（本次账号是单店，未取到多店实样）

| 字段 | 位置 | 本账号取值 |
|---|---|---|
| `isSingleHotelViewer` | `window.MicroMainConfig` | `true` |
| `companyGroupTypeIsMultiHotelGroup` | `getHotelInfo()` | `false` |
| `companyGroupTypeIsCtripHotelGroup` | `getHotelInfo()` | `false` |
| `isHotelCompany` | `getHotelInfo()` | `false` |
| `hotelList` | `getHotelInfo()` | `[123326337, 115348672, 115355969, 117203890, 115582769]` |
| `getMgrGroupInfo()` | 全局 API | 四个字段全空 |

⚠️ **`hotelList` 存疑**：本账号 `isSingleHotelViewer: true` 却有 5 个 ID，且量级（9 位）
与 `masterHotelId`（8 位）不同，**大概率不是可绑定门店**（疑似子房型/子酒店），
不要直接当门店候选用。多门店语义应以 `companyGroupTypeIsMultiHotelGroup` /
`getMgrGroupInfo()` 为准。**需要一个真实多门店账号复验后才能定方案。**

## 现有代码的取数方式（对照）

`main/channels/ctrip/hotel-dom.ts` 的 `READ_CTRIP_HOTELS_EXPRESSION` 读的是
DOM 里的 `a.he-ctrip-hotel-title-link`，从 href 抠 `/hotels/(\d+)`：

- 只拿得到**酒店**，拿不到账号 —— 所以 `discovery.ts:51` 只能拿酒店 ID 充当 `channelAccountId`
- 依赖 class 名，携程改版即失效；`HEAppInfo` 是官方 SDK，稳定性更高
- 多门店时该选择器返回多条 → `kind: 'multiple'` → 整条链路放弃（T4 的 bug）
